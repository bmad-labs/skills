# Guide — 09-data-pipeline

Level: Medium. Tool: hand SVG from a generator on a frontier model (skill `references/svg-diagrams.md`); PlantUML
activity diagram otherwise.

## pipeline.svg — Pipeline of one unit of work

**Purpose.** The whole life of one unit of work on one page: every step, every exit, and who owns each.

**Rules (must).**
- Generated by `tools/render_pipeline.py`; never edited by hand.
- One box per step, left to right in order. One dashed exit box under each step that has an exit.
- Colour means owner or kind (ours, external, wait, exit), never decoration. README has the colour code.
- Every exit ends somewhere visible (a state, a task, a count). An exit that ends nowhere is a design gap: raise it.
- Hand-offs between lanes carry the message code and transport.
- Root: `viewBox`, `width`, `height` equal; `preserveAspectRatio="xMidYMid meet"`; numeric XML entities only.

**How to fill.**
1. Take the pipeline from the user's image or the canon. One row of `STEPS` per step.
2. Add each exit from the sequences (refusal, failure, timeout, ignore).
3. Run the generator; render to PNG; look at every connector zoomed.

**Best practices.**
- ≤ ~10 steps per lane. More lanes rather than a longer spine.
- Compute gaps from the width; change `BOX_W` or the copy, never the font size, when text does not fit.
- Caption each lane with its owner.

**Check.** `xmllint --noout`; render to PNG at 2× and check text fit, arrow landing, even gaps; every lane step has
a detail link in README.
